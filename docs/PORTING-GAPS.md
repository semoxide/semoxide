# Porting gaps

What semantic-release does that semoxide can't reproduce as-is in Rust, and what replaces it. The overview is in [semantic-release §6](research/semantic-release.md#6-rust-port-notes). `semoxide migrate` ([ADR 0001](decisions/0001-compatibility-stance.md)) reports every gap it hits in a user's `.releaserc`.

| # | Gap | semantic-release behavior | Why it can't be ported as-is | semoxide replacement | Decision link |
|---|---|---|---|---|---|
| 1 | JS config files | cosmiconfig: `.releaserc*`, `release.config.(js\|ts\|mjs\|cjs)`, `package.json#release` ([spec §3](specs/SEMANTIC-RELEASE-SPEC.md#3-configuration)) | Options in JS/TS files can be computed or be functions | `semoxide.toml`, data only | [0002](decisions/0002-config-format.md) |
| 2 | Plugin loading | `import()` of npm modules, CJS/ESM interop, inline function plugins ([flow](research/semantic-release.md#plugin-loading-and-normalization)) | No JS runtime | Compiled-in plugins plus subprocess plugins over a JSON-RPC protocol. | 3 | Shareable configs | npm packages, plugins resolved relative to the config package ([spec §10](specs/SEMANTIC-RELEASE-SPEC.md#10-shareable-configs)) | npm resolution | `extends` with non-executable TOML sources ([table](research/distribution-config.md#shareable-configs-no-npm)) | [0002](decisions/0002-config-format.md) (layer); sources **open** |
| 4 | lodash templates | `${...}` / `<% %>` run arbitrary JS in `tagFormat`, branch props, git `message`, exec `*Cmd`, github templates ([dependencies §10](research/dependencies.md#10-lodash-template-usage)) | `new Function` eval | `{version}` for `tag_format`, minijinja elsewhere | [0004](decisions/0004-template-engine.md) |

| 11 | Mutating `process.env` | Core sets `GIT_ASKPASS`, `GIT_TERMINAL_PROMPT`, `GIT_AUTHOR_*`/`GIT_COMMITTER_*` on the caller's env ([run order](research/semantic-release.md#run-internals)) | Library anti-pattern; `set_var` is `unsafe` in edition 2024; git2 takes credentials/signatures via API | Explicit env map in the context; bot identity and credentials passed to git2 via callbacks/`Signature`; children get a built env | **open** |

| 13 | `npm` CLI dependency | Bundled `npm` for version/pack/publish/whoami/dist-tag, temp npmrc ([npm §5](research/npm.md#5-rust-port-notes)) | Packing, lifecycle scripts and provenance only exist in the CLI | Shell out to the user's PM for pack/publish only; native HTTP for whoami, OIDC, dist-tags | **open** |
| 14 | Error semantics | `SemanticReleaseError` with a `semanticRelease` flag that gates `fail`; `AggregateError` flattening ([error aggregation](research/semantic-release.md#error-aggregation), [error §9](research/dependencies.md#9-semantic-releaseerror)) | Duck-typed marker flag on any thrown object | `thiserror` enum with `code()`, `details`, `is_user_facing()`, aggregated as `Vec` | **open** |

## Open decisions

Recommendations only; the user decides.

1. **Plugin mechanism (#2):** hybrid: compiled-in built-ins behind cargo features, third-party plugins as subprocesses over JSON-RPC stdio; WASM deferred. Confirmed by [poc/plugin-protocol](../poc/plugin-protocol/README.md).
2. **`extends` sources (#3):** v1 supports built-in presets and local paths; git refs pinned to a SHA and HTTPS URLs with `sha256` come in v1.x; no npm runtime resolution.
3. **User functions (#5):** declarative config only: section map, hidden types, sort keys, rule list with glob values. No function rules; custom logic goes into an `analyze_commits`/`generate_notes` plugin.
4. **Preset set (#6):** ship `angular` and `conventionalcommits` as built-in data frozen at parser 7.1.2 / presets 9.4 and 10.4; default `angular` for parity, same reasoning as [ADR 0007](decisions/0007-bump-defaults.md); user presets as TOML.
5. **Glob semantics (#7):** `globset` without extglob, `*` crosses `/` in rule values. Maintenance branches use a built-in matcher equivalent to the default extglob. `migrate` rewrites extglobs it recognizes and reports the rest.
6. **Ranges (#8):** depend on `semver` for `Version`; write an own `Range { min, max_exclusive }` and bump functions with node-semver prerelease rules covered by ported test cases; no `nodejs-semver` dependency.
7. **User regexes (#9):** `regex` crate only (linear time, no ReDoS). `migrate` flags patterns that use lookaround or backrefs.
8. **Secret masking (#10):** masking designed into the output sink and every subprocess/plugin pipe; specify it in [Observability](OBSERVABILITY.md).
9. **Env handling (#11):** never mutate the process env; the context carries an injectable env map.
10. **CI detection (#12):** own table-driven env-ci port as a separate module/crate.
11. **npm (#13):** shell out for pack/publish, native HTTP for the rest; ship the npm plugin as an optional cargo feature, not in the default set.
12. **Errors (#14):** `thiserror` enum plus `Vec` aggregation; only user-facing errors reach `fail`, same as upstream.
13. **Library API (#15):** `Semoxide::builder()` taking the config layers, `cwd`, env map, output sinks and plugins; returns `Ok(None)` for no release.
14. **Sort order (#16):** case-insensitive comparison with byte-order tiebreak, documented as a difference.
